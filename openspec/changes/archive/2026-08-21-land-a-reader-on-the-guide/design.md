## Context

The guide is written once, in `docs/guide/<locale>/`, and rendered by
`website/`. Everything below has to hold that line: a page must stay readable in
a file browser and in a vault, and the site must not become a second place where
prose lives. `website/scripts/sync-docs.mjs` is the only seam where the two
surfaces are allowed to differ, and it is where most of this change lands.

Two facts about the site as built decided several of the choices:

- The copy under `website/src/content/docs/` is generated and git-ignored, so
  Starlight can read no history from it. A date has to come from the guide page
  the copy was made from.
- Astro 7 renders Markdown with its own processor. `starlight-image-zoom`, the
  obvious way to make figures open, refuses to load under it and asks for the
  previous processor; pinning that processor back needs
  `@astrojs/markdown-remark@7.2.2` where `@astrojs/mdx` already requires 7.2.4.
  The plugin is one dialog, one listener and one `<img>`.

## Goals / Non-Goals

Goals:

- A reader arriving from the store is told what the plugin is and how to get it,
  in the locale they arrived in.
- A shared link carries a picture.
- A figure can be read at the size it was captured, on a phone as on a desktop.
- A passage that constrains the reader looks different from one that explains.
- Everything the page loads still comes from this site's own origin.

Non-Goals:

- Rewriting guide prose. A paragraph promoted to a callout keeps its words.
- A second navigation scheme, a versioned guide, or a blog.
- Making the Chinese guide the source of a plain-text copy: the generator reads
  the default locale, and a half-translated `llms.txt` is worse than one locale
  honestly stated.

## Decisions

**The hero's sentence is guide prose; the hero's buttons are not.** The tagline
is one `tagline:` line in each locale's `README.md` frontmatter, so a translator
owns it and a file browser shows it as one more frontmatter row. The three
button labels are the same three actions on every page of the site — chrome, not
prose — so they sit in the sync script beside the other locale-dependent
plumbing, exactly as the sidebar's group headings sit in the site config.

**The hero carries no picture.** The guide's own first figure is one paragraph
below it, and a hero image would be that figure twice. Starlight reserves a
second column for an image regardless, so the site's stylesheet returns an
image-less hero to one centred column rather than leaving a hole on a wide
screen.

**The workflow table becomes cards, or stays a table.** The index page's table
is a list of links wearing a table's clothes: two columns, every second cell a
single link. Only a table of exactly that shape is converted, and only on the
index page; anything else is left untouched, so this cannot quietly mangle a
real table. The converted page is the one page emitted as MDX.

**Alerts, not directives.** The guide writes `> [!NOTE]`, which GitHub renders
as a callout, Obsidian renders as a callout, and every other Markdown viewer
renders as a blockquote — never as a broken directive. The sync script turns
each into a Starlight aside. `IMPORTANT` and `WARNING` both become `caution`,
and no aside is given a title, so Starlight titles it in the locale being read
and neither locale's file has to carry a translated label.

**Figures open through a button.** Each figure is wrapped in a real button, so
the keyboard reaches it and a screen reader is told it is a control rather than
a picture; the dialog it opens is a `<dialog>`, closed by Escape or by a click.
The dialog shows the widest candidate in the figure's own `srcset`, which is the
whole point: the responsive build makes a smaller copy for the page, and the
largest copy is what a reader opening a figure wants. The script is inlined into
the page, because it is smaller than the request that would fetch it.

**The date is the prose's date.** `git log -1` on the guide page, written into
the generated copy's frontmatter as a timestamp. This makes the publishing
workflow's checkout depth part of the contract: a shallow clone dates every page
from the tip commit, so `docs.yml` fetches the full history.

## Risks / Trade-offs

- **A hand-written dialog is code this project now owns.** It is ~60 lines with
  no dependency, and the alternative was pinning the whole site's Markdown
  processor backwards for one plugin. If `starlight-image-zoom` gains support
  for the current processor, this can be deleted for it.
- **MDX for one page.** `@astrojs/mdx` is already a Starlight dependency, so the
  cost is a line in the config rather than a new tree; the risk is that the
  index page now fails differently from the other nine. The card conversion
  degrades to the original table rather than throwing.
- **The preview card is a committed binary.** It is regenerated by hand with
  `npm run card` when the screenshot, the name, or the colours change, and it is
  reviewed like any other figure. Generating it in CI would make the published
  bytes depend on which fonts a runner has.
- **`llms.txt` is English only.** Stated here rather than discovered later.
