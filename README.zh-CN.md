# Advanced Maps

[![CI](https://github.com/Jin1c-3/obsidian-advanced-maps/actions/workflows/ci.yml/badge.svg)](https://github.com/Jin1c-3/obsidian-advanced-maps/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

**简体中文** · [English](README.md)

给 Obsidian 内置的 **Maps** 视图做加法，而不是另起炉灶：GPX、GeoJSON、KML、TCX
轨迹，带距离、累计爬升和高程剖面；一键缩放到全部；国内坐标系；内联
`![[track.gpx]]` 地图；⋮ 菜单里的「在地图中打开」，以及跟着当前笔记走的侧边栏地
图；一行代码嵌入一张「本篇相关笔记的地图」；以及三种填坐标的方式——粘贴分享链接、
搜索地名，或者直接取当前位置（桌面端同样可用）。

内置视图已经做好的部分——标记、图标、颜色、底图、气泡、右键菜单——仍然由内置视图
来做。不带 Leaflet，不内嵌任何地图库，没有任何运行时依赖。

![国内底图上的 Bases 地图视图：从笔记附件读出的 13.6 公里 GPX 环线，每篇笔记的图钉是它自己的颜色](docs/map-view.png)

## 它解决什么问题

| 问题                                                                     | 这个插件的做法                                                                                                     |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------ |
| 笔记里附了一条散步的 `.gpx`，地图上却只有一个图钉。                      | 把轨迹画出来，用这篇笔记自己的颜色。悬停出气泡，点击打开笔记。                                                     |
| 一条轨迹只是一根线——看不出走的方向，也看不出起点和终点在哪。             | 起点图钉、不一样的终点图钉，加上沿线的方向箭头。带名字的途经点，内联地图上悬停可见。                               |
| `.gpx` 明明记着你走了多远、爬了多少，却没人告诉你。                      | 内联地图下方给出距离、累计爬升、移动时间和平均速度，再配一张高程剖面——悬停它能在地图上找到对应的点，反过来也一样。 |
| 国内底图不是 WGS-84，每个图钉都偏出好几条街，最多能差一公里。            | 绘制时换算过去，读回来时换算回来。磁盘上什么都不动，笔记里仍然是 WGS-84。                                          |
| 地图一打开是整个世界，或者停在配置里随手写的那个点。                     | 自动框住标记**和**轨迹；你一拖动它就让开。⛶ 按钮随时重新框选。                                                     |
| 笔记里的 `![[track.gpx]]` 只渲染成一个链接。                             | 直接渲染成一张真的地图。去掉 `!`，轨迹照样上每一张 base 地图，笔记里不会多出第二张图。                             |
| 只想看某一篇笔记在地图上的位置，不想去 base 里翻。                       | 笔记 ⋮ 菜单里的「在地图中打开」，打开你自己 base 的地图视图，把镜头移到这篇笔记并弹出气泡。                        |
| 侧边栏挂着一张地图，和正在写的笔记各走各的。                             | 让它跟着走：切到哪篇笔记，镜头就移到哪。base 的查询条件一个字都不动。                                              |
| 一篇游记涉及六个地方，而一篇笔记只能放一个坐标。                         | 一行嵌入一张「相关笔记的地图」——它链接的、链接它的，以及它自己。拖一篇笔记进来就出现。                             |
| 别人发来一个地图分享链接，还得自己把数字抠出来——顺序要对，坐标系也要对。 | 粘进去就行。不管原来是什么坐标系，写进笔记的都是 WGS-84。                                                          |
| 知道地方叫什么，但不知道在哪儿。                                         | 搜一下，从列表里挑。                                                                                               |
| 手动填坐标。                                                             | 把模板里空着的 `coords:` 用当前位置补上——桌面端也可以，之前的插件都跳过了这一块。                                  |

## 环境要求

- Obsidian 1.13.1 或更新版本，并启用 **Bases**（核心插件）。
- 第一方 **Maps** 插件——这个插件扩展的就是它提供的视图。没装的话 Advanced Maps
  会提示一句，然后什么都不做。

## 安装

**从 Release 安装。** 到
[Releases](https://github.com/Jin1c-3/obsidian-advanced-maps/releases) 下载
`main.js`、`manifest.json` 和 `styles.css`，放进
`<库>/.obsidian/plugins/advanced-maps/`，然后在「设置 → 第三方插件」里启用。

**用 BRAT 安装。** 在 [BRAT](https://github.com/TfTHacker/obsidian42-brat) 里添加
`Jin1c-3/obsidian-advanced-maps`。

## 怎么用

### 轨迹

给笔记附上 `.gpx`、`.geojson`、`.kml` 或 `.tcx`——`![[2026-04-12.gpx]]`——凡是
base 里包含这篇笔记的地图视图，都会把轨迹画出来。不用配置，也不用为了让附件进入结
果集而放宽 base 的筛选条件。直接用 `file.ext == "gpx"` 查询的 base 同样有效。

普通链接 `[[2026-04-12.gpx]]`，或者写在属性里的 `track: "[[2026-04-12.gpx]]"`，
一样算数——这也就是**只要地图上的轨迹、不要笔记里的地图**的说法。区别就在那个
`!`，和它在 Obsidian 里一贯的含义一致：带 `!`，每张 base 地图上都有这条线，笔记里
再多一张内联地图；不带 `!`，就只有那条线。笔记里本来已经有一张地图时，这一点值得
记住。

每条轨迹还会带上一个起点图钉、一个形状不同的终点图钉，以及沿线指示方向的箭头——
base 地图视图和内联地图都一样。带名字的途经点悬停会显示名称，但只在内联地图上：
base 视图的悬停已经会弹出笔记自己的气泡，同一次悬停再叠一个提示框只会互相打架，而
不是相得益彰。**显示轨迹标记**这一项设置默认开启，一次性把这些都关掉。

### 内联地图，以及轨迹本身知道的事

同一个嵌入语法，在笔记里就渲染成一张真地图——可以拖、可以缩放、可以切底图——下面
配上这个文件一直带着、却从没人读给你听的那些数字。

![笔记里嵌入的 .gpx 渲染成一张实时地图，下面一行是距离、爬升、时间和平均速度，再下面是高程剖面](docs/inline-embed.png)

距离、累计爬升与下降、海拔范围、总时长与移动时间，还有平均速度。文件里没记的那几
项直接不显示，而不是显示成 0——`.geojson` 通常既没有高程也没有时间戳，那它就只有一
个距离。把鼠标停在任意一个数字上可以看到它是什么。这一行和剖面图都可以在设置里关
掉。

剖面图和地图是双向联动的：把鼠标停在剖面图上，地图上的轨迹会出现一个跟着移动的
点；把鼠标停在地图上的轨迹上，剖面图上也会出现同一个点。只在内联地图里生效——base
地图视图没有剖面图可联动。

其中有两个数字比看上去讲究，而且都取了偏保守的算法：**累计爬升**会忽略 5 米以内的
抖动，因为 GPS 原始高程的噪声足以把一段平路累成几百米的虚假爬升；**移动时间**把
0.9 km/h 以上都算作在动——这个门槛足够低，低到爬楼梯也仍然算走路。

地图只在滚动到可视区域时才创建，因为每张地图都占用一个 WebGL 上下文，而浏览器对同
时存活的数量有上限。文件扩展名只在没有别的插件认领时才接管，所以已经能渲染 `.gpx`
的插件可以和它共存。

### 视图选项

内置选项一个都不动，只往后追加两组——**轨迹**排在「标记」后面，**坐标系**排在「背
景」后面，紧挨着决定它的瓦片 URL。

| 选项         | 含义                     |
| ------------ | ------------------------ |
| 线宽         | 轨迹线的宽度             |
| 线条透明度   | 轨迹线的透明度           |
| 自动缩放上限 | 自动框选时最多放大到几级 |
| 瓦片坐标系   | 留空则跟随插件设置       |

### 坐标系

![同一条 WGS-84 轨迹、同一张底图，换算关掉再打开：轨迹从山坡上挪回到它真正走过的那条堤上](docs/coordinate-systems.gif)

两帧是同一个 `.gpx`、同一套瓦片。关掉时这段路穿过宝石山；打开后它落在白堤上——差
约 520 米，而且每个图钉都跟着一起挪。

保持**自动**，坐标系就由瓦片 URL 决定：提供 GCJ-02 或 BD-09 的国内服务按域名识别，
其余一律按 WGS-84 处理。也可以在插件设置里指定默认值，或者在某个视图里强制指定
——代理过的瓦片 URL 看不出它到底来自哪家时就需要这样。

### 在其他地图应用里打开

在地图视图上右键。除了内置的几项——在此新建笔记、复制坐标、设为默认中心点——还有
一项_用外部地图打开_。

![地图的右键菜单，「用外部地图打开」展开出高德、百度、腾讯、Google、Apple 和 OpenStreetMap 的子菜单](docs/external-map.png)

每个应用收到的都是它真正期望的坐标系，从你点击的那个点换算而来：高德和腾讯用
GCJ-02，百度用 BD-09，Google 和 Apple 则视这个点在不在国内而定 WGS-84 还是 GCJ-02。
难点全在这里——同样这六条链接，随手拼出来会以三种不同的方式落错地方，而且在你真的
站到错误的街口之前，一种都看不出来。

这六个由你自己安排，在设置的**用外部地图打开**里。拖成你实际会用的顺序，用不上的
关掉——菜单是有限的，五个你根本没装的应用就是五行要略过的字。六个全关掉，地图的右
键菜单里就不会多出任何东西。

下面的**自定义**一开始是空的。一条记录由名称、URL 和这个 URL 期待的坐标系组成：

| 字段   | 填什么                                                   |
| ------ | -------------------------------------------------------- |
| 名称   | 菜单里显示的文字                                         |
| URL    | 用 `{lat}` 和 `{lng}` 标出数字的位置，先后顺序随目标应用 |
| 坐标系 | WGS-84、GCJ-02 或 BD-09——这个 URL 期待哪个               |

```
https://ul.waze.com/ul?ll={lat},{lng}&navigate=yes      WGS-84
https://uri.amap.com/marker?position={lng},{lat}         GCJ-02
om://map?v=1&ll={lat},{lng}                              WGS-84
```

应用协议和网址一样能用——`waze://`、`iosamap://`、`comgooglemaps://`——只要设备上装
了那个应用。真正值得停下来想一想的是坐标系那一栏：它由你说明，而不是由插件去猜，因
为一个国内服务商的自建镜像看上去和普通域名没有区别，而猜错不会报错，只会把标记放到
隔几条街的地方。

### 一个 base，处处复用

下面两个功能值得放在一起理解，因为它们共用同一个想法：**你只维护一个 `.base` 文
件，库里的每一张地图都是这个 base 换一副筛选条件之后的样子。**

在设置里把 **Base 文件路径**指向它，一次就够——这一栏会列出库里的 `.base` 文件，点
一下就能选，不用记也不用敲路径。从此这个 base 就回答了一张地图必须定下来的全部三个
问题：

| 问题                 | 答案在哪里                                  |
| -------------------- | ------------------------------------------- |
| 哪些笔记算「地点」？ | base 自己的筛选条件——目录、标签、属性都行   |
| 图钉长什么样？       | base 的公式，经由**标记图标**和**标记颜色** |
| 坐标存在哪儿？       | 地图视图的**坐标**属性                      |

所以你只需调一次外观，所有地图都跟着变：⋮ 菜单打开的那张、侧边栏跟着你走的那张，以
及库里任何位置嵌入的每一张「周围」地图。加一条新图标的公式，它会在所有地图上出现，
连之前插入的也一样
——因为它们都没有复制你的 base，而是引用它。一篇展示地图的笔记只带一行、不带任何配
置，这也正是这些地图能够被随意编辑、移动或被别的东西同步而不出问题的原因。

有好几组互不相干的地点？各建一个 base 就好——**Base 文件路径**只是指明命令用的是
哪一个。

### 在地图中打开

带有坐标属性（默认是 `coords`）的笔记，会在 ⋮ 菜单和命令面板里多出一项_在地图中打
开_。**视图名称**列出的是这个 base 里的地图视图，选「第一个地图视图」就是取排在最
前面的那个——在一个 base 只有一个地图视图之前，这就够了。打开的就是你自己的 base，带着
你的筛选、颜色和图标——只是把镜头移到了这篇笔记上，并弹出它的气泡。base 既不会被复
制，也不会被改写。

![base 的地图视图打开在某一篇笔记上：镜头落在楼外楼，它自己的图钉和气泡，周围仍然是这个 base 的其他地点](docs/open-in-map.png)

**打开方式**决定它出现在哪：

- **标签页**（默认）打开的是 base 文件本身，已经打开该 base 的标签页会被复用，不会
  越开越多——所以连着对好几篇笔记按这一项，就是同一张地图在移动。因为那是真正的文
  件，你在地图上做的改动——「设为默认中心点」、切换底图——都会留下来。
- **弹窗**不动你的布局，嵌入的是同一个视图。代价写在这里而不是留给你自己发现：嵌入
  的 base 没有地方回写视图设置，所以在弹窗里改的东西关掉就没了。

### 跟随当前笔记

打开**跟随当前笔记**之后，**侧边栏**里的地图会跟着你切换的笔记移动，并弹出它的气
泡。主区域的地图永远不跟——那一张是你正在看的东西，不是取景器。缩放保持你自己调的，
base 的查询条件一个字都不动：动的只有镜头。

![编辑器里打开着一篇笔记，侧边栏里同一个 base 的地图移到了这篇笔记的坐标上，气泡打开着](docs/follow-active-note.png)

### 本篇相关笔记的地图

一篇游记会涉及好几个地点，而每个地点通常本来就已经是一篇笔记了。_插入本篇相关笔记
的地图_——在编辑器里右键，或者用命令面板——会往你当前所在的笔记里写一行：

```
![[places.base#周围]]
```

它是你自己 base 里的一个视图，筛选条件是：这篇笔记**链接到的**笔记、**链接到它
的**笔记，以及它自己。第一次执行命令时这个视图会被加进 base，之后每次都只是引用
它——所以真正干活的是你的 base，而你之后对 base 做的改动，会传导到每一张已经插入的
地图上。

在那之后插件就退场了。把一篇笔记拖进正文——Obsidian 一如既往地生成一个链接——它就
出现在地图上，带着你的 base 给它的颜色、图标和气泡。删掉链接它就消失。没有需要维护
的列表，真相也不存在第二个地方：笔记周围的那些链接**就是**这张地图。

两个方向都算数，所以一篇提到了当前笔记的笔记——后续记录、子条目，任何带着反向链接
的东西——完全不用编辑就会自己出现。当前笔记本身，只要有了自己的坐标就加入，清空坐
标就退出，因此你永远不需要把一篇笔记链接到它自己。

它读取的 **Base 文件路径**和**视图名称**与_在地图中打开_是同一份，新加的视图是从那
个地图视图复制来的，所以标记会沿用你的坐标属性、图标和颜色。它的中心和缩放级别留
空，这样它才能框住你目前收集到的全部内容。

有两处边界值得知道：

- **链接是按视图名称指过去的。** 在 Bases 里改名——或者在**「周围」视图名称**里改
  ——已经插入的地图会静悄悄地失效。Obsidian 不会替你重写 `#view` 片段。
- **base 自己的筛选条件仍然生效。** 如果你的 base 限定在某个目录内，那么放在这个目
  录外面的笔记可以把别的笔记收集到地图上，却没法把自己放上去。

### 从地图链接填写坐标

位置信息几乎从来不是以坐标的形式到达的——它是以别人手机上的一条分享链接到达的。
_从地图链接填写坐标_接收这样一条链接，把笔记的坐标属性填上。

![粘贴框读出了一条分享链接，并显示它将写入的 WGS-84 坐标](docs/link-modal.png)

它能读常见的国内和国际地图应用生成的分享链接，另外还支持
`geo:30.26,120.15`、度分秒（`30°15'39"N 120°08'49"E`）和纯坐标 `30.26,120.15`。每
种形式都按它自己的规则来读，因为它们在轴顺序和坐标系上都各执一词——有的经度在前，
有的是 GCJ-02，有的是 BD-09，有的是 WGS-84，还有的取决于这个点在哪儿。

不管进去的是什么，**出来的都是 WGS-84**——而且在写入之前会先把坐标系显示给你看，
因为坐标系错了的坐标在笔记里看起来毫无破绽，图钉却会落到隔壁省。当纯数字来自一个
链接无法透露的来源时，可以用下拉框覆盖掉自动识别的结果。

打开时框里已经填好了你剪贴板上的内容，因为那几乎总是你要粘的那条链接——只在打开时
读一次，而且不会发往任何地方。

短链接在被解析之前不含任何坐标，而这个插件不会为了解析它而悄悄把你的链接交给第三
方。自己打开一次，再把跳转后的地址粘进来。

### 地点搜索

_搜索地点并填写坐标_把一个名字查出来，并写入返回的结果。地名会按你自己的 Obsidian
语言给出。

![搜索框里列出了四个国家中十个同名地点，每一个下面都带着它的地址](docs/place-search.png)

设置里有两个搜索源可选：一个面向全球、不用注册但国内 POI 很少，另一个是国内的，需
要你自己申请一个免费的 Web 服务 key，但对国内地点熟得多。返回 GCJ-02 的搜索源会在
写入时换算，和其他所有环节一样。

这个 key 可以放在两个地方，因为哪个更合适没有普适答案。**密钥存储**是 Obsidian 自带
的：key 不会进入插件的设置文件，也就不会被同步、备份或提交；代价是它只留在这一台设
备上，每台要搜索的设备都得各填一次。**插件设置**把它和其他设置放在一起，填一次全设
备通用，但是明文。新安装默认用密钥存储；在这个选项出现之前就填好的 key 会留在原处，
直到你自己搬动它，而切换时 key 会被一并搬过去，不会丢。

加上下面这条命令，这是**插件自己发起的两次请求之一**：出去的要么是你输入的内容，要
么——对另一条命令来说——是你让它查的那一个坐标，发往你选的那个搜索源。没有遥测，不
含笔记内容。

不过它并不是一张地图产生的全部流量——见[有哪些数据会离开你的库](#有哪些数据会离开你的库)。

### 从坐标填写地名

_从坐标填写地名_是反过来的方向：读取笔记的坐标属性，把查到的地址写回另一个属
性——设置里的**地名属性**，默认 `location`。它会覆盖那里原有的内容，理由和_用当前定
位填写坐标_会覆盖一样：手动执行一条命令本身就是明确的要求。

它沿用你在上面地点搜索里配置的搜索源和 key。当搜索源是高德时，坐标会先换算成
GCJ-02 再发出去——高德的逆地理编码接口期待的坐标系，和它的正向搜索返回的是同一个。

和从链接填写坐标一样，这条命令也**不**受**启用定位**开关控制：它不会弹出权限询问，
也不会记录这台设备在哪里。但和从链接填写坐标不同的是，它确实会把你已有的一个坐标发
给第三方——见[有哪些数据会离开你的库](#有哪些数据会离开你的库)。

### 定位

打开**启用定位**，坐标属性_存在但为空_的笔记就会被填上你当前的位置。给模板留一行空
的 `coords:`，由它生成的每篇笔记都会被打上位置。已经有值的属性绝不会被覆盖，没有这
个属性的笔记也不会凭空多出一个。_用当前定位填写坐标_命令则是按需覆盖。

写入格式是 WGS-84 的 `纬度,经度`——比如 `28.624415,115.788091`。路径中包含**跳过路
径包含**里任一片段（默认 `templates`）的笔记会被放过。

桌面端和移动端都能用，而之前的插件在这里放弃了：当前的 Chromium 会向操作系统要位
置，不涉及任何 API key。这仍然取决于系统定位服务是开着的——在 Linux 上还取决于
GeoClue 能不能用——所以插件只问一次，平台一旦拒绝，本次启动就不再问。细节和一段用来
测试自己机器的控制台代码见 [CLAUDE.md](CLAUDE.md#why-location-is-not-mobile-only)。

## 有哪些数据会离开你的库

简短版本：你的笔记和轨迹不会自己跑出去——唯一的例外，是你主动交给_从坐标填写地名_的
那一个坐标。下面列出的，要么是地图没它就没法工作的，要么是你主动要求的。

| 什么时候               | 出去的是什么                             | 发往哪里                       |
| ---------------------- | ---------------------------------------- | ------------------------------ |
| 任何地图显示在屏幕上时 | 瓦片请求，也就是你的 IP 和你正在看的区域 | 该视图所设置的那个底图服务     |
| 你在搜索框里输入时     | 你输入的词、你的语言、你填的 key（如有） | 你选的那个搜索源               |
| 你运行_从坐标填写地名_ | 你运行它所用的那一个坐标                 | 你选的那个搜索源               |
| 你选了_用外部地图打开_ | 你右键点的那一个点，出现在浏览器标签页里 | 你选的那个地图应用，在浏览器中 |
| 你打开**启用定位**     | 什么都不出去——位置来自操作系统           | —                              |

插件没有遥测，没有更新探测，也没有自己的服务器。轨迹文件和笔记内容从不被传输，你已有
的坐标也是——唯独_从坐标填写地名_是个例外，它存在的意义正是把一个坐标发出去，查回那
里是什么地方。粘贴的短链接**不会**替你解析，恰恰是因为那意味着把它交给第三方。

如果你是给别人部署而不是自己用，有两点值得注意：搜索 key 不论存在哪里，都会出现在请
求 URL 中——密钥存储让它不落在设置文件里，但不会让它从查询里消失；另外，一篇笔记的坐
标历史在某种意义上属于个人信息，而笔记正文不是。这两点对个人使用都没问题，用在别的
场景则值得再看一眼。

## 素材来源

截图是在第三方底图和搜索服务上拍的，只用于展示插件做了什么，别无他意；每张图都标注
了来源。它们背后的演示库是合成的：其中的地点、路线及其高程都是公开发布的数据，没有

插件本身不附带任何地图数据。它只绘制视图所配置的瓦片，而这些瓦片的版权、许可以及可
能涉及的测绘审批要求属于瓦片提供方和使用者，不属于这个插件。如果你拥有此处复现的任
何内容的权利并希望撤下，请[提一个
issue](https://github.com/Jin1c-3/obsidian-advanced-maps/issues)，会尽快处理。

## 开发

```bash
git clone https://github.com/Jin1c-3/obsidian-advanced-maps
cd obsidian-advanced-maps
npm install
cp .env.example .env      # 把 OBSIDIAN_PLUGIN_DIR 指向一个库
npm run dev               # 监听、重新构建进那个库、热重载
npm run check             # prettier、eslint、tsc、vitest —— 和 CI 跑的是同一套
```

`npm run dev` 会把构建产物直接写进库目录，并在旁边放一个 `.hotreload` 标记文件，这
正是 [pjeby/hot-reload](https://github.com/pjeby/hot-reload) 监视的东西——装一次那
个插件，之后每次保存都会重载 Advanced Maps，不用碰 Obsidian。

你需要一个开启了 **Bases** 并装有第一方 **Maps** 插件的库；否则这个插件没有可扩展的
对象。

- [ROADMAP.md](ROADMAP.md) —— 接下来可能会做什么、明确不会做什么，以及每一项的接
  口在哪里。
- [CLAUDE.md](CLAUDE.md) —— 架构、所依赖的内部实现、坐标流水线，以及那些不该动的非
  显而易见之处。
- [CONTRIBUTING.md](CONTRIBUTING.md) —— 环境搭建、测试覆盖了什么、打补丁代码的规
  矩、翻译。

## 翻译

`src/i18n.ts` 里每种语言一张扁平的表；英文是事实来源，它的键就是类型，所以漏掉一
条会直接编译报错。新增一种语言＝一个对象加 `LOCALES` 里的一行。
