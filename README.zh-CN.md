# Advanced Maps

[![CI](https://github.com/Jin1c-3/obsidian-advanced-maps/actions/workflows/ci.yml/badge.svg)](https://github.com/Jin1c-3/obsidian-advanced-maps/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

**简体中文** · [English](README.md)

给 Obsidian 内置的 **Maps** 视图做加法，而不是另起炉灶：GPX 轨迹、国内坐标系、内联
地图，以及三种填坐标的方式。内置视图已经做好的部分——标记、图标、颜色、底图、气
泡——仍然由内置视图来做。不带 Leaflet，不内嵌任何地图库，没有任何运行时依赖。

![国内底图上的 Bases 地图视图：从笔记附件读出的 13.6 公里 GPX 环线，每篇笔记的图钉是它自己的颜色](docs/map-view.png)

## 它解决什么问题

| 问题                                                   | 这个插件的做法                                         |
| ------------------------------------------------------ | ------------------------------------------------------ |
| 笔记里附了 `.gpx`，地图上却只有一个图钉。              | 用这篇笔记自己的颜色画出轨迹，带起终点图钉和方向箭头。 |
| `.gpx` 记着你走了多远，却没人告诉你。                  | 距离、爬升、移动时间、配速，外加一张可悬停的高程剖面。 |
| 国内底图不是 WGS-84，图钉能偏出好几条街。              | 绘制时换算过去，读回来时换算回来。磁盘上什么都不动。   |
| 地图一打开是整个世界。                                 | 自动框住标记**和**轨迹；你一拖动它就让开。             |
| 笔记里的 `![[track.gpx]]` 只渲染成一个链接。           | 直接渲染成一张真的地图。                               |
| 笔记旁边那张地图，和你正在写的笔记各走各的。           | 按一下 ⊹ 就跟着走。base 的查询条件一个字都不动。       |
| 一篇游记涉及六个地方，一篇笔记只能放一个坐标。         | 一行嵌入一张「相关笔记的地图」。拖一篇笔记进来就出现。 |
| 收到一条分享链接，还得自己抠数字，还得猜是什么坐标系。 | 粘进去就行。不管原来是什么，写进笔记的都是 WGS-84。    |
| 手动填坐标。                                           | 搜地名，或者直接取当前位置——桌面端同样可用。           |

## 环境要求

Obsidian 1.13.1 或更新版本，启用 **Bases**，并装上第一方的 **Maps** 插件——这个插件
扩展的就是它提供的视图。没装的话 Advanced Maps 会提示一句，然后什么都不做。

## 安装

**从 Release 安装。** 到
[Releases](https://github.com/Jin1c-3/obsidian-advanced-maps/releases) 下载
`main.js`、`manifest.json` 和 `styles.css`，放进
`<库>/.obsidian/plugins/advanced-maps/` 并启用。

**用 BRAT 安装。** 添加 `Jin1c-3/obsidian-advanced-maps`。

## 轨迹

给笔记附上 `.gpx`、`.geojson`、`.kml` 或 `.tcx`，凡是 base 里包含这篇笔记的地图视
图，都会把轨迹画出来。不用配置，也不用为了让附件进入结果集而放宽筛选条件。

那个 `!` 决定笔记里要不要也长出一张地图：`![[walk.gpx]]` 是每张 base 地图上都有这条
线**外加**笔记里一张内联地图；`[[walk.gpx]]`——或者写在属性里的
`track: "[[walk.gpx]]"`——就只有那条线。

每条轨迹都会带上起点图钉、形状不同的终点图钉，以及沿线指示方向的箭头。带名字的途经点
在内联地图上悬停可见。**显示轨迹标记**一次性把这些都关掉。

![横穿长堤的一条 GPX 轨迹：起点是一个绿色实心圆，终点是一个红色圆环，线上的箭头指着当时走的方向](docs/track-markers.png)

## 内联地图

同一个嵌入语法，在笔记里就渲染成一张真地图——可以拖、可以缩放、可以切底图——下面配上
这个文件一直带着、却从没人读给你听的那些数字。

![笔记里嵌入的 .gpx 渲染成一张实时地图，下面一行是距离、爬升、时间和平均速度，再下面是高程剖面](docs/inline-embed.png)

距离、累计爬升与下降、海拔范围、总时长与移动时间、平均速度。文件里没记的那几项直接不
显示，而不是显示成 0。把鼠标停在任意一个数字上可以看到它是什么；停在剖面图上，地图的
轨迹会出现一个跟着移动的点，反过来也一样。这一行和剖面图都可以关掉。

有两个数字比看上去讲究：**累计爬升**会忽略 5 米以内的抖动，因为 GPS 原始高程的噪声足
以把一段平路累成几百米的虚假爬升；**移动时间**把 0.9 km/h 以上都算作在动，低到爬楼梯
也仍然算走路。

## 视图选项

内置选项一个都不动，只往后追加两组——**轨迹**排在「标记」后面，**坐标系**排在「背景」
后面。

| 选项         | 含义                     |
| ------------ | ------------------------ |
| 线宽         | 轨迹线的宽度             |
| 线条透明度   | 轨迹线的透明度           |
| 自动缩放上限 | 自动框选时最多放大到几级 |
| 瓦片坐标系   | 留空则跟随插件设置       |

## 坐标系

![同一条 WGS-84 轨迹、同一张底图，换算关掉再打开：轨迹从山坡上挪回到它真正走过的那条堤上](docs/coordinate-systems.gif)

两帧是同一个 `.gpx`、同一套瓦片。关掉时这段路穿过宝石山；打开后它落在白堤上——差约
520 米，而且每个图钉都跟着一起挪。

保持**自动**，坐标系就由瓦片 URL 决定：提供 GCJ-02 或 BD-09 的国内服务按域名识别，其
余一律按 WGS-84 处理。也可以在设置里指定默认值，或者在某个视图里强制指定——代理过的瓦
片 URL 看不出它到底来自哪家时就需要这样。

## 在其他地图应用里打开

在地图上右键。除了内置的那几项，还有一项_用外部地图打开_。

![地图的右键菜单，「用外部地图打开」展开出高德、百度、腾讯、Google、Apple 和 OpenStreetMap 的子菜单](docs/external-map.png)

每个应用收到的都是它真正期望的坐标系，从你点击的那个点换算而来：高德和腾讯用 GCJ-02，
百度用 BD-09，Google 和 Apple 则视这个点在不在国内而定。难点全在这里——同样这六条链
接，随手拼出来会以三种不同的方式落错地方，而且在你真的站到错误的街口之前，一种都看不
出来。

这六个在设置的**用外部地图打开**里由你自己排序，用不上的关掉，六个全关掉地图的右键菜
单里就不会多出任何东西。下面的**自定义**一开始是空的，一条记录由名称、URL 和这个 URL
期待的坐标系组成：

```
https://ul.waze.com/ul?ll={lat},{lng}&navigate=yes      WGS-84
https://uri.amap.com/marker?position={lng},{lat}        GCJ-02
om://map?v=1&ll={lat},{lng}                             WGS-84
```

应用协议和网址一样能用——`waze://`、`iosamap://`、`comgooglemaps://`。坐标系那一栏由你
说明而不是由插件去猜：一个国内服务商的自建镜像看上去和普通域名没有区别，而猜错不会报
错，只会把标记放到隔几条街的地方。

## 一个 base，处处复用

**你只维护一个 `.base` 文件，库里的每一张地图都是这个 base 换一副筛选条件之后的样
子。** 在设置里把 **Base 文件路径**指向它，一次就够——这一栏会列出库里的 `.base` 文
件，点一下就能选。从此这个 base 就回答了一张地图必须定下来的全部三个问题：

| 问题                 | 答案在哪里                                  |
| -------------------- | ------------------------------------------- |
| 哪些笔记算「地点」？ | base 自己的筛选条件——目录、标签、属性都行   |
| 图钉长什么样？       | base 的公式，经由**标记图标**和**标记颜色** |
| 坐标存在哪儿？       | 地图视图的**坐标**属性                      |

调一次外观，所有地图都跟着变，连之前插入的也一样——因为它们都没有复制你的 base，而是
引用它。有好几组互不相干的地点？各建一个 base 就好，**Base 文件路径**只是指明命令用的
是哪一个。

### 在地图中打开

带有坐标属性（默认是 `coords`）的笔记，⋮ 菜单里会多出一项_在地图中打开_。打开的就是
你自己的 base，带着你的筛选、颜色和图标——只是把镜头移到了这篇笔记上，并弹出它的气
泡。base 既不会被复制，也不会被改写。

![base 的地图视图打开在某一篇笔记上：镜头落在楼外楼，它自己的图钉和气泡，周围仍然是这个 base 的其他地点](docs/open-in-map.png)

**打开方式**决定它出现在哪。**标签页**打开的是 base 文件本身，已经打开该 base 的标签
页会被复用——所以连着对好几篇笔记按这一项，就是同一张地图在移动；因为那是真正的文件，
你在地图上做的改动都会留下来。**弹窗**不动你的布局，代价是嵌入的 base 没有地方回写视
图设置。

### 跟随当前笔记

每张地图的「缩放到全部」按钮旁边都有一个 ⊹ 按钮。按下之后，这张地图就会跟着你切换的笔
记移动，并弹出它的气泡。缩放保持你自己调的，base 的查询条件一个字都不动：动的只有镜
头。

![一个标签页里是笔记，隔壁标签页里是同一个 base 的地图，镜头移到了这篇笔记的坐标上，气泡开着，跟随按钮亮着](docs/follow-active-note.png)

它是一张地图一个开关，不是一个插件一个开关——侧边栏那张、和你笔记并排那张可以一起跟着
走，另一个标签页里你正在看的那张纹丝不动。跟随中的地图还会让着你：气泡照常弹出，但不
会把光标从编辑器里抢走；点击图钉会**在这张地图正在跟随的那一栏里**打开笔记，而不是把
地图本身顶掉。设置里的**新地图默认跟随当前笔记**决定按钮的初始状态。

### 本篇相关笔记的地图

_插入本篇相关笔记的地图_ 会往你所在的笔记里写一行：

```
![[places.base#周围]]
```

![一篇游记，里面的地点就是普通的双链，下面一张地图把它们逐个标了出来](docs/around-map.png)

它是你自己 base 里的一个视图，筛选条件是这篇笔记**链接到的**、**链接到它的**，以及它
自己。往正文里拖一篇笔记——Obsidian 会照常建立链接——它就出现在地图上；删掉链接它就消
失。没有第二份名单要维护：笔记周围的链接**就是**这张地图。

视图第一次使用命令时加进 base，之后都是引用，所以你后来改动 base，已经插入的每一张地
图都会跟着变。两处边界：**链接里带着视图名**，在 Bases 里改名会让已插入的地图静默失
效；**base 自己的筛选条件仍然生效**，所以一篇放在目录范围之外的笔记可以把别的笔记收集
到地图上，却没法把自己放上去。

## 怎么把坐标填进去

### 从地图链接

一个位置很少以坐标的形式到你手上，它通常是一条分享链接。_从地图链接设置坐标_ 接住
它，把坐标填进属性。

![粘贴框读出了一条分享链接，并显示它将要写入的 WGS-84 坐标](docs/link-modal.png)

它认识常见国内外地图应用产生的分享链接，另外还有 `geo:30.26,120.15`、度分秒
（`30°15'39"N 120°08'49"E`）和纯数字 `30.26,120.15`。每一种都按它自己的规则读，因为它
们在轴顺序和坐标系上都不一致。不管进去的是什么，**出来的都是 WGS-84**，而且在写入之前
先把坐标系告诉你。

粘贴框打开时会自动带上剪贴板里的内容。短链接在解析之前不含坐标，而这个插件不会背着你
把你的链接交给第三方去解析。

### 靠搜地名

_搜索地点并设置坐标_ 查一个名字，把结果写进去，条目用你自己的 Obsidian 语言显示。

![搜索框列出了四个国家里十个同名地点，每个下面是它的地址](docs/place-search.png)

两个数据源：一个开放的全球源，不用注册，但国内 POI 很薄；一个国内源，需要你自己的免费
Web 服务 key，但认识得多得多。以 GCJ-02 作答的源会在写入前换算过来。

key 可以放在 **secret storage**（Obsidian 自己的，不进设置文件、不会被同步或提交，代价
是只留在这一台设备上），也可以放在**插件设置**里（一处填写覆盖所有设备，明文）。新装
默认用 secret storage；这个设置出现之前就存在的 key 会留在原地，直到你自己搬。

### 反过来，从坐标填地名

_从坐标填写地名_ 读笔记的坐标属性，把地址写回**地名属性**（默认 `location`）。它复用
地点搜索那一套数据源和 key。如果把两个属性设成同一个名字，命令会直接拒绝，而不是用地
址覆盖掉它刚读出来的坐标。

### 从当前位置

打开**启用定位**，坐标属性**存在但为空**的笔记会被填上你所在的位置——给模板留一个空的
`coords:`，用它新建的每篇笔记都会被打上坐标。已经有值的永远不会被覆盖，没有这个属性的
笔记也永远不会凭空多出一个。_用当前位置填写坐标_ 命令则按需覆盖。

写入的是 WGS-84 的 `lat,lng`。路径命中**跳过包含以下片段的路径**（默认 `templates`）的
笔记会被放过。桌面端同样可用——之前的插件都跳过了这一块：现在的 Chromium 直接问操作系
统，不涉及任何 API key。这仍然取决于系统定位服务是否开着，所以插件只问一次，平台拒绝之
后本次启动不再打扰。

## 什么会离开你的库

你的笔记和轨迹不会自己去任何地方。唯一的例外是你主动交给_从坐标填写地名_的那一个坐标。

| 什么时候               | 出去的是什么                             | 去哪里                     |
| ---------------------- | ---------------------------------------- | -------------------------- |
| 只要有地图在屏幕上     | 瓦片请求，也就是你的 IP 和你正在看的区域 | 该视图设定的底图服务       |
| 你在搜索框里打字       | 你输入的词、你的语言、你填的 key（如有） | 你选的搜索源               |
| 你运行_从坐标填写地名_ | 你运行它的那一个坐标                     | 你选的搜索源               |
| 你选_用外部地图打开_   | 你右键的那一个点，在那个浏览器标签页里   | 你选的地图应用，在浏览器里 |
| 你打开**启用定位**     | 什么都不出去——位置来自操作系统           | —                          |

没有遥测，没有更新检查，也没有自己的服务器。如果你是给别人部署而不是自己用，有两点值得
知道：搜索 key 无论存在哪里都会出现在请求 URL 里——secret storage 让它不进设置文件，但
不会让它不进查询串；另外，一篇笔记的坐标记录在某种意义上比正文更算个人信息。

## 开发

```bash
git clone https://github.com/Jin1c-3/obsidian-advanced-maps
cd obsidian-advanced-maps
npm install
cp .env.example .env      # 把 OBSIDIAN_PLUGIN_DIR 指向一个库
npm run dev               # 监听、重建到那个库、热重载
npm run check             # prettier、eslint、tsc、vitest——和 CI 跑的是同一套
```

`npm run dev` 会在产物旁边放一个 `.hotreload` 标记，
[pjeby/hot-reload](https://github.com/pjeby/hot-reload) 认的就是它。你需要一个开了
**Bases**、并装有第一方 **Maps** 插件的库。

- [ROADMAP.md](ROADMAP.md)：接下来可能做什么，以及明确不做什么。
- [CLAUDE.md](CLAUDE.md)：架构、依赖的内部接口，以及那些不该动的地方。
- [CONTRIBUTING.md](CONTRIBUTING.md)：环境、测试、代码约定、翻译。

新增一种语言：`src/i18n.ts` 里一个对象，加上 `LOCALES` 里一行。英文是事实来源，它的键
就是类型，所以漏一条会直接编译报错。
